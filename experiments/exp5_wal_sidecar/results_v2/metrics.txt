EXP 5 (v2) — In-tree adaptive group-commit AOF
Modified Redis 6.2.14 + new appendfsync mode `groupcommit`
Defaults: aof-groupcommit-window-ms=20, aof-groupcommit-max-bytes=65536

EXPERIMENT 1 — Crash durability (kill -9 after 2.0s of writes)
================================================================
Method: write as fast as one client can, then SIGKILL the process group.
Restart, replay AOF, count surviving keys. Also report theoretical
worst-case loss window in ms (the operator-relevant metric).

Metric                            | everysec     | always      | groupcommit  | Change vs everysec
----------------------------------|--------------|-------------|--------------|---------------------
Writes acked before kill          | 18,237       | 536         | 6,046        | (groupcommit -> 33%)
AOF size at kill (bytes)          | 2,133,752    | 62,735      | 707,405      |
AOF size on disk after kill       | 2,133,752    | 62,735      | 707,405      | identical (page cache)
Lost writes after restart         | 0            | 0           | 0            | (ext4 journal preserves)
Theoretical max loss window (ms)  | 1,000        | 0           | 20           | 50x tighter
Theoretical max lost writes       | 9,118        | 0           | 60           | 152x fewer

Note: zero observed losses in all modes is a kernel artifact (ext4 data=ordered
flushes the journal). The theoretical-window column is the *true* operator
exposure: in a power-loss event (page cache wiped), everysec loses up to 1s
of writes; groupcommit caps loss at the configured 20ms window.

KEY INVARIANT — tunability proved
================================================================
With aof-groupcommit-window-ms=20:
  expected fsyncs over 5s = 50/s * 5s = 250
  observed: 250 (resource), 251 (burst)
  -> the adaptive timer fires exactly at the configured cadence under load.

With aof-groupcommit-max-bytes=65536:
  byte-trigger only fires if a 5s burst writes >65kB BETWEEN windows.
  observed byte_triggers: 0 (in all runs) -> the time window dominates,
  byte trigger acts as a safety net for pathological 1-byte values that
  inflate the aof_buf without elapsing window time.
